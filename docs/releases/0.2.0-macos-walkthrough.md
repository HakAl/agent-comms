# Release 0.2.0: walkthrough on a clean Mac

This is the release evidence for 0.2.0 and the acceptance walkthrough of
milestone 1 of the [roadmap](../ROADMAP.md): on a clean Mac, following only
this repository's docs, install a release, run setup against a project, pick
runtimes and create a small team, get a clean `doctor` report, run the
fake-runtime demo, then a real dispatch, review and approval. Every command
below was run as the docs give it, in the order shown, and its exit status
and the relevant lines of its output are recorded. Where the walkthrough had
to depart from the doc text, the departure is marked and listed under
[Departures](#departures-from-the-docs). The record is a frozen snapshot of
one run; it is not parsed by the docs checker and is not kept in step with
later doc changes.

The VM clock is UTC and agreed with the host; timestamps in the output are
the VM's. The record is a scrub of the raw transcripts: the home directory
is written `~`, the VM user's name never appears (`<user>` where a command
echoed it), signer lines show `ssh-ed25519 <public key>`, device codes,
fingerprints and account details are `<redacted>`, and every id is one the
walkthrough itself generated. No signature is included in this record: the
operator-reported signing excerpts omit it (`push_approval create` prints
the whole record it wrote, signature included, and the operator reported
only its first line), and `push_approval show` displays the signed fields
and the unsigned advisory data, not the signature. `[...]` marks lines left
out. Each command ran in a login shell over
ssh; `exit=` is the exit status of the whole block.

1. **Release candidate checkout.** One `git checkout <commit>` line added to
   the quickstart's install block, so the VM installed the candidate rather
   than `main` (the record lands after the run).
2. **`uv sync --python 3.14`.** The clone's `uv sync` fails on a Mac whose
   only Python at or above 3.11 is 3.15 (ac-o7y); the walkthrough pinned the interpreter and
   uv downloaded it. The wheel install was not affected.
3. **`mkdir -p <runtime root>/codex-auth` and `--device-auth`.** The
   doctor fix for the shared Codex login does not run as printed (ac-zkn),
   and a headless machine has no browser for the default login flow.

   `claude -p` with the operating rules as an appended system prompt and
   `--allowedTools "mcp__agent-comms__*"`, instead of an interactive
   session with the rules pasted, because the walkthrough drives the VM
   over ssh. The seat launcher, the MCP binding and the dispatch path are
   the same.

   shell; `AGENT_COMMS_ADMIN_TOKEN` was exported again before the `admin`
   command.

   detached process writing to `~/monitor.log`.

   Claude custody copy in, their own Codex, and the workers' shared Codex
